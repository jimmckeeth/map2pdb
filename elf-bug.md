# Bug Report: map2pdb Parsing Failure on Linux ELF Map Files

## 1. Symptoms and Error Message
When running `map2pdb` on a `.map` file generated by the Delphi Linux compiler (`dcclinux64 -GD`), the program terminates with a fatal error:

```text
map2pdb project32.map
map2pdb - Copyright (c) 2021 Anders Melander
Version 3.3.9236.32134

Fatal: [ 6473] Invalid 64-bit hex number: "\program files ("
```

## 3. Analysis of the Failure
The error message `Invalid 64-bit hex number: "\program files ("` originates from the `HexToInt64` function in `debug.info.reader.map.pas`. 

### The Root Cause:
1.  **Format Mismatch:** The `TDebugInfoMapReader` is designed for traditional Delphi (`0001:00401000`) and C++ Builder map formats. It is not currently equipped to handle the GNU/ELF map format produced by the Linux compiler, which uses `0x` prefixes and different column layouts.
2.  **State Misalignment:** The parser likely misidentified a section (e.g., thought it found the "Modules" or "Line numbers" section) and began attempting to parse addresses.
3.  **Parsing Logic:** `HexToInt64` was called with an index pointing directly to the backslash in the path `c:\program files...`. Because the first character (`\`) is not a valid hex digit, `HexToNibble` returned `$FF`, the loop broke immediately, and because the index hadn't moved (`Offset = FirstOffset`), a fatal error was raised.

## 4. Relevant Source Code (map2pdb)

### `debug.info.reader.map.pas`: The parser implementation
```pascal
function TDebugInfoMapReader.HexToInt64(const s: string; var Offset: integer): Int64;
begin
  Result := 0;
  var FirstOffset := Offset;
  var i := SizeOf(Result) * 2; // 16 characters for 64-bit hex
  while (i > 0) and (Offset <= Length(s)) do
  begin
    var Nibble := HexToNibble(s[Offset]);
    if (Nibble = $FF) then
      break;

    Result := (Result SHL 4) or Nibble;
    Inc(Offset);
    Dec(i);
  end;

  if (Offset = FirstOffset) then
    // This is where it fails: Copy(s, FirstOffset, 16) yields "\program files ("
    LineLogger.Error('Invalid %d-bit hex number: "%s"', [SizeOf(Result)*8, Copy(s, FirstOffset, SizeOf(Result)*2)])
  else
  if (Offset <= Length(s)) and (CharInSet(s[Offset], ['H', 'h'])) then
    Inc(Offset); 
end;
```

### `map2pdb.dpr`: Reader selection logic

## 5. Context from "Building for Linux" Guide
- **Compiler Command:** `dcclinux64.exe Project32.dpr -GD`
- **Linker:** `ld-linux.exe` (GNU Gold Linker 1.12)
- **Problem:** The resulting `.map` file contains Windows paths (from the Delphi library) inside an ELF-style map, which confuses the standard Delphi MAP parser.

## 6. Proposed Path Forward
To fix this, `map2pdb` likely needs:
1.  **A New Reader:** `TDebugInfoElfMapReader` specifically for the format used by the Linux/Android/iOS LLVM compilers.
2.  **Improved Robustness:** `TDebugInfoMapReader` should be modified to gracefully skip lines it doesn't recognize rather than throwing fatal errors when it encounters unexpected characters (like spaces or backslashes) in a field it expects to be hex.
3.  **Path Sanitization:** The parser should be updated to handle spaces in file paths, which are common in "Program Files" on Windows even when targeting Linux.
